# Tutorial de implementacao da API e integracoes

Este guia mostra como preparar a API Fiber NET Telecom, conectar IXC, Supabase, IA e OpenWA, e validar o fluxo do chatbot pelo WhatsApp.

## 1. Pre-requisitos

- Node.js 20 ou superior.
- Acesso ao IXC Provedor com URL e token Basic.
- Projeto Supabase, se quiser persistir cache e conversas.
- Provedor de IA configurado, preferencialmente OpenRouter/OpenAI ou um dos providers ja suportados.
- Instancia do OpenWA `rmyndharis/OpenWA` rodando e acessivel pela API.
- URL publica HTTPS para receber webhooks em producao.

## 2. Instalar a API

```bash
npm ci
cp .env.example .env
```

Edite `.env` com os dados reais do ambiente.

```bash
npm run build
npm run dev
```

Verifique:

```bash
curl http://localhost:3001/api/health
```

Resposta esperada:

```json
{
  "status": "healthy"
}
```

## 3. Configurar IXC

Variaveis:

```env
IXC_BASE_URL=https://seu-ixc/webservice/v1
IXC_AUTH_BASIC=
IXC_TIMEOUT=30000
IXC_RETRIES=3
IXC_RETRY_DELAY=1000
```

O token deve ser informado sem expor no codigo. O service central fica em `src/services/ixcService.ts` e ja concentra clientes, contratos, financeiro, PIX, boletos, logins e desbloqueio.

Valide uma rota publica simples:

```bash
curl -X POST http://localhost:3001/api/buscar \
  -H "Content-Type: application/json" \
  -d '{"cpfCnpj":"00000000000"}'
```

## 4. Configurar Supabase

Variaveis:

```env
SUPABASE_URL=
SUPABASE_KEY=
```

Crie a tabela de cache:

```sql
create table if not exists cache (
  key text primary key,
  value text not null,
  expires_at timestamp
);
```

Crie as tabelas do chatbot:

```sql
create table if not exists chatbot_conversations (
  id text primary key,
  phone text not null,
  customer_id integer,
  contract_id integer,
  status text not null,
  funnel_state text,
  created_at timestamptz not null,
  updated_at timestamptz not null
);

create table if not exists chatbot_messages (
  id bigint generated by default as identity primary key,
  conversation_id text not null references chatbot_conversations(id),
  direction text not null,
  content text not null,
  intent text,
  origin text not null,
  external_message_id text,
  created_at timestamptz not null
);

create table if not exists chatbot_events (
  id bigint generated by default as identity primary key,
  event_type text,
  payload jsonb,
  created_at timestamptz not null
);
```

Sem Supabase configurado, conversas usam memoria apenas para desenvolvimento e testes.

## 5. Configurar IA

O chatbot usa a camada existente em `src/services/ai`. Configure pelo menos um provider:

```env
OPENROUTER_API_KEY=
OPENROUTER_MODEL=google/gemini-2.0-flash-lite-preview-02-05:free
```

Tambem e possivel usar:

```env
OPENAI_API_KEY=
ANTHROPIC_API_KEY=
GOOGLE_API_KEY=
GROQ_API_KEY=
```

A IA nao decide regras de negocio. Ela classifica intencao e reformula respostas aprovadas pelas regras deterministicas.

## 6. Configurar OpenWA

Variaveis:

```env
OPENWA_URL=http://localhost:2785
OPENWA_API_KEY=
OPENWA_SESSION=
OPENWA_WEBHOOK_SECRET=
```

Notas:

- `OPENWA_URL` e a URL base da API OpenWA.
- `OPENWA_API_KEY` e enviada no header `X-API-Key`.
- `OPENWA_SESSION` e o ID/UUID da sessao usado em `/api/sessions/:sessionId`.
- `OPENWA_WEBHOOK_SECRET` valida `X-OpenWA-Signature`.

Teste o status da sessao:

```bash
curl http://localhost:3001/api/whatsapp/status
```

Teste envio manual:

```bash
curl -X POST http://localhost:3001/api/whatsapp/send \
  -H "Content-Type: application/json" \
  -d '{"phone":"5524999999999","message":"Teste Fiber NET"}'
```

Internamente a API envia:

```http
POST /api/sessions/:sessionId/messages/send-text
X-API-Key: <OPENWA_API_KEY>
```

Com payload:

```json
{
  "chatId": "5524999999999@c.us",
  "text": "Teste Fiber NET"
}
```

## 7. Registrar webhook no OpenWA

Configure no OpenWA o webhook apontando para:

```text
https://backend.fibernettelecom.com/api/whatsapp/webhook
```

Eventos recomendados:

```json
["message.received", "session.status"]
```

Payload esperado pela API:

```json
{
  "event": "message.received",
  "data": {
    "id": "msg-123",
    "sender": "5524999999999@c.us",
    "chatId": "5524999999999@c.us",
    "body": "Minha internet esta bloqueada",
    "isGroup": false,
    "fromMe": false
  }
}
```

Se `OPENWA_WEBHOOK_SECRET` estiver definido, envie `X-OpenWA-Signature` no formato:

```text
sha256=<hmac_sha256_do_raw_body>
```

## 8. Configurar chatbot

Variaveis:

```env
CHATBOT_ENABLED=true
CHATBOT_MAX_HISTORY=12
CHATBOT_TIMEOUT=30000
```

Endpoint direto para teste:

```bash
curl -X POST http://localhost:3001/api/chatbot/message \
  -H "Content-Type: application/json" \
  -d '{"phone":"5524999999999","message":"Minha internet esta bloqueada"}'
```

Resposta esperada:

```json
{
  "success": true,
  "reply": "Ola, Joao. Encontrei seu contrato...",
  "customer": {
    "id": 2984,
    "name": "JOAO PEDRO"
  },
  "status": "reativacao"
}
```

Se o telefone nao identificar cliente, a resposta solicita CPF/CNPJ.

## 9. Fluxo completo

1. Cliente envia mensagem no WhatsApp.
2. OpenWA recebe e dispara webhook.
3. API valida assinatura, duplicidade, grupo, bot e payload.
4. API normaliza telefone.
5. Chatbot busca cliente no IXC por telefone.
6. Chatbot consulta contratos, financeiro e logins.
7. Regras deterministicas classificam bloqueio, fatura e funil.
8. IA interpreta intencao e reformula a resposta aprovada.
9. Conversa e mensagens sao salvas.
10. API envia resposta pelo OpenWA.

## 10. Endpoints principais

Chatbot:

```text
POST /api/chatbot/message
GET  /api/chatbot/conversations/:phone
```

WhatsApp:

```text
POST /api/whatsapp/webhook
GET  /api/whatsapp/status
POST /api/whatsapp/send
```

Reativacao:

```text
GET  /api/reativacao/bloqueados
GET  /api/reativacao/:customerId
POST /api/reativacao/registrar
```

Financeiro existente:

```text
POST /api/buscar
GET  /api/pix/:id
GET  /api/boletos/:fatura_id/segunda-via
```

## 11. Testes e build

Build:

```bash
npm run build
```

Testes focados do chatbot e OpenWA:

```bash
npm test -- --runTestsByPath \
  src/whatsapp/openwa.service.test.ts \
  src/whatsapp/webhook.service.test.ts \
  src/chatbot/service.test.ts \
  src/reativacao/rules.test.ts
```

A suite completa pode depender de ajustes legados e permissoes do ambiente de teste para listeners HTTP.

## 12. Deploy

Checklist antes de publicar:

- `.env` preenchido no provedor de deploy.
- `IXC_BASE_URL` e `IXC_AUTH_BASIC` validos.
- `OPENWA_URL` acessivel pelo backend.
- `OPENWA_WEBHOOK_SECRET` configurado nos dois lados.
- `CHATBOT_ENABLED=true`.
- Tabelas Supabase criadas, se persistencia for necessaria.
- `npm run build` passando.

Depois do deploy, valide:

```bash
curl https://backend.fibernettelecom.com/api/health
curl https://backend.fibernettelecom.com/api/whatsapp/status
```

## 13. Operacao segura

- Nunca registre tokens, chaves ou segredos em logs.
- Nao permita que IA confirme pagamento, desbloqueio, desconto ou parcelamento.
- Use handoff humano para cancelamento, reclamacao, baixa confianca e casos fora do fluxo.
- Monitore erros de IXC, OpenWA e IA separadamente.
- Mantenha o webhook protegido por HMAC sempre que possivel.
