# Chatbot Telecom Fiber Net

O chatbot roda dentro do backend existente e usa o fluxo:

WhatsApp -> OpenWA -> `/api/whatsapp/webhook` -> `ChatbotService` -> IXC -> regras de negocio -> IA -> OpenWA.

## Endpoints

- `POST /api/chatbot/message`
- `GET /api/chatbot/conversations/:phone`

## Banco sugerido

```sql
create table chatbot_conversations (
  id text primary key,
  phone text not null,
  customer_id integer,
  contract_id integer,
  status text not null,
  funnel_state text,
  created_at timestamptz not null,
  updated_at timestamptz not null
);

create table chatbot_messages (
  id bigint generated by default as identity primary key,
  conversation_id text not null references chatbot_conversations(id),
  direction text not null,
  content text not null,
  intent text,
  origin text not null,
  external_message_id text,
  created_at timestamptz not null
);

create table chatbot_events (
  id bigint generated by default as identity primary key,
  event_type text,
  payload jsonb,
  created_at timestamptz not null
);
```

Sem Supabase configurado, o modulo usa memoria apenas para desenvolvimento/testes.

## IA

A IA classifica intencao e reformula texto, mas nao decide valor, desconto, prazo, desbloqueio, parcelamento ou autorizacao.
